# 这次应该验证复制成本

本示例中的岗位、候选人与项目均为虚构，不构成市场研究或真人评级。

小林已经在一个部门试用了资料核查助手，保存了测试样本、失败记录和实际使用反馈。如果建议她“先做一个有用户的AI任务”，会重复已经完成的工作。她下一步需要确认：换一个部门后，这项能力还能否用合理的成本交付。

## 为什么选择这个问题

假设她的目标岗位负责多客户企业应用，职责同时要求任务效果与标准化交付。现有项目已经说明她能在特定资料、规则与用户习惯下推进试用，却尚未说明哪些依赖可以复用。第二个客户需要重新维护所有资料、提示词与流程时，单个项目有价值，也可能尚未具备产品化条件。

因此要比较两种解释：核心流程已经通用，只需要配置；或者原来的效果高度依赖项目定制。两种解释会产生不同投资，不能只用“已经上线”作结论。

## 怎样作出下一次决定

| 观察 | 对投入的影响 |
|---|---|
| 换资料后流程仍适用，差异来自版本与权限配置 | 优先完善配置与交付说明 |
| 新部门的审核标准、任务步骤完全不同 | 先重做任务分析，再判断是否属于同一产品 |
| 迁移后人工核验过重 | 检查数据与结果标准，不急着推广更多用户 |

建议选择一个不同部门作对照，记录共享流程、必要配置、额外维护和验收差异。结果可能是扩大，也可能是缩小适用范围。这里的成果是有依据地决定产品边界，不能预先承诺规模化成功。
