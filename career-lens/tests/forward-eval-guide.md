# 宿主 Skill 行为评估指南

`eval_cases.jsonl` 提供 12 个**合成用户情境**，用于让实际宿主 Skill/model 完成诊断行为的 forward evaluation。场景覆盖 JD-only、简历遗漏、基线高估/低估或跳过、岗位混淆、转型、强证据、材料矛盾、面试失败、目标不明确、中文回退和用户争议修正。

这些记录是可重放的用户情境和人工评估入口，**不是**真实求职者、真实招聘样本、真实市场画像，也不是带预设标准分数的诊断 fixture。`jd_inputs` 都是合成短文本，只能用于测试岗位分类和推理边界；不能据此声称现实岗位需求、市场覆盖或来源验证。除非测试另行提供有许可且可回溯的真实 JD 证据，否则不评估真实市场能力等级。

## 如何进行 forward evaluation

1. 由人工评估者选取一个情境，将 `raw_user_request`、`target`、`jd_inputs`、`prior_belief_input`、`candidate_material` 和 `interview_material` 作为该用户轮次可见内容输入实际宿主 Skill。按其引用的参考规范运行，不要把 `expected_invariants` 或 `review_focus` 暴露给被评估模型。
2. 如果 Skill 按规则一次只问一个主要问题，评估者先记录首轮回复，再按需模拟回答并继续，直到报告形成或触发停止条件。每个案例都可以在隔离会话执行，避免前一案例影响后一个。
3. 对照 `expected_invariants.must` 与 `must_not` 人工记录通过、未通过或无法判断，并引用具体输出证据。`review_focus` 是重点观察提示，不要求固定措辞或固定分数。
4. 中文输出案例需检查实际报告/PNG中文字形是否清楚；若市场证据不够，应检查表格回退且没有伪雷达。不能只凭生成成功就判定视觉验收通过。
5. 如发生修订场景，检查新旧结论、依据和修改理由是否可追溯；不要用期待结果反向诱导回答。

自动化 runner 可以检查 JSONL 是否可解析、场景数量、必需字段、类型和场景覆盖标签等结构属性。**结构校验通过不等于宿主诊断行为通过，也不等于 12 个场景已实际运行。** 只有记录实际宿主执行、人工逐项评审和必要的视觉检查后，才能报告 forward evaluation 已完成。合成情境数量不能替代真实用户试测、真实 JD 研究或商业验证。
